## 视觉方向：草地小伙伴

首页采用中性的暖灰白、深海军蓝品牌字和原图标。两张等权卡片，以各自预览展示区别；背景不使用太空或草地装饰。卡片整体可点，明确进入“设置座位”。品牌始终是 RabbitPlaneChess。

2D 使用奶油白棋盘、浅草绿背景、圆角色块和统一深色细轮廓。角色为原创 SVG 小头像，无 emoji 字体依赖、无位图缩放和外部字体请求。

| 固定 seat | 角色 | 轮廓特征 | 身份补充 |
| --- | --- | --- | --- |
| 0 红 | 小兔 | 长耳、白脸、粉耳心 | 珊瑚红围巾与编号徽章 |
| 1 绿 | 青蛙 | 两个圆形眼冠、宽脸 | 叶绿围巾与编号徽章 |
| 2 黄 | 小猫 | 三角耳、金黄脸 | 蜂蜜黄围巾、深棕编号 |
| 3 蓝 | 企鹅 | 深蓝外轮廓、白脸、小尖喙 | 天蓝围巾与编号徽章 |

四方各四枚，每枚显示 1–4 编号。棋盘上的小伙伴是游戏角色，不替换品牌图标。正式共享格棋子约 28–32px；头像与徽章保持在该格的可读范围，四枚叠放用格内四象限小幅排布，高亮当前候选，侧栏/底部独立按钮始终可选。

棋盘直接按原 15×15 坐标绘制，基地为 5×5；52 个共享格各色 13 格。出生格使用共享格实际颜色和前进箭头。归航道每方 6 格，第六格深色标“终”；中心小芽圆盘限制在中心空格，不覆盖四个终点。

快速通道细虚线取实际行动方颜色，不取端点颜色；端点箭头均在格内，不添加圆点。选中相关动作时加强该方通道，动画采用跨越和影子位移，不能逐格绕行。中点撞击表现为小伙伴弹回营地；阶段结算仍由核心执行。

桌面布局：顶部品牌和主题首页按钮；左侧玩家列表；中央完整正方形棋盘；右侧回合、骰子、候选编号和设置/重开。1280×720 棋盘约 554px，1440×810 约 644px。2D 不提供俯视/3D/跟随控制。3D 继续保留原相机与空间构图，不套用 2D 布局。

主题文案集中在配置：飞机→小伙伴，机库/基地→营地，起飞→出发，击落→送回营地，快速飞行→快速跨越，归航道→回家小路；内部状态名称完全不变。设置的红绿黄蓝、人类、简单电脑、聪明电脑和 TEST MODE 语义一致。

## 页面与 URL 行为

正式方案采用 query + hash，不需要静态服务 rewrite：

| 地址或操作 | 预期行为 |
| --- | --- |
| / 或 /index.html，无游戏配置参数 | 主题首页，不导入 Three.js、不建场景。 |
| /?theme=acrylic | 3D 座位设置；设置背景使用静态预览，开始时按需加载 Three.js 与场景。 |
| /?theme=cartoon | 2D 座位设置；开始时只加载 SVG 表现模块。 |
| 存在 n/t/l/test/auto，缺省 theme | 按原逻辑解释配置并落到 3D；auto=1 才自动新开局。未知参数不触发旧游戏兼容。 |
| theme 无效 | 回主题首页，说明主题不可用，保留可用的座位配置。 |
| 开始对局 | 当前 URL 保留主题及有效配置，hash 进入 #play；内存持有当前局。 |
| 正常刷新或直达 #play | 没有可恢复会话，replace 为当前主题设置，不声称恢复对局。明确 auto=1 的链接按原约定新开局。 |
| 显式 auto=1 | 加载后跳过设置开新局；进入设置或首页时移除 auto，防止用户返回设置后被再次自动开局。 |
| 设置返回首页 | push 进入无配置的 /，草稿配置仅在当前标签页会话内保留；从首页再选主题进入设置。 |
| 对局中返回首页/设置/重开 | “离开将结束当前对局，进度不会保存。”确认后才取消旧会话和导航；取消保持当前局。 |
| 浏览器前进/后退 | 首页与设置依历史路由恢复；离开活跃对局同样确认，取消恢复当前历史位置；已经结束的 #play 历史条目归一化到设置，不复活旧局。 |
| 刷新或关闭活跃页面 | 使用浏览器 beforeunload 默认提示（受浏览器交互策略限制）；无存档承诺。 |
| 安装入口 | manifest 的 id=/、start_url=/、name/short_name 与 icons 保持；主题色可随统一首页调整，不更换安装身份。 |

设计 HTML 中使用 #home/#setup2d/#setup3d/#game 只是浏览效果稿的页签，不是正式路由实现。按钮未运行掷骰、AI、退出确认或真实对局；本阶段不做可玩性声明。

## 最小代码拆分

```text
public/index.html                 共用页面容器与品牌元数据
public/js/app.js                  URL 解析、首页/设置/对局导航、会话生命周期
public/js/board.js                原坐标与逻辑位置映射
public/js/game.js                 原状态、合法动作、骰子、回合、结算与 AI
public/js/ui.js                   座位、玩家条、候选按钮、结果面板
public/themes/catalog.js          主题名称、预览、色板、文案、动态 import 入口
public/themes/acrylic.js          原 Three.js 模型、相机、场景、动画、拾取
public/themes/cartoon.js          SVG 棋盘、动物、动画、拾取
public/styles/…                  共用布局及两主题样式
```

不引入框架、构建器、第二套规则或持久化对局。表现接口保持小规模：mount、render、animateStage、showChoices、resize、dispose。核心阶段包含行走、首落点、+4、快进落点、穿越中点、出口、完成；无动画时消费同样阶段，产生同样最终状态。对于取消的局，旧 Promise 不得向新 state 提交。

dispose 必须取消 RAF/定时器、解除监听、取消待处理输入；3D 遍历释放 geometry/material/texture 和 renderer，移除 canvas；同局重开也创建新的会话令牌。正在加载的主题完成后仍需检查令牌，过期加载不能挂载。

## 第二阶段验收计划

先保存当前逻辑基线，用固定 state 与骰子验证同色 +4、直接/间接快速通道、各阶段撞子、50→51、56 折返、己方叠放。保留现有动作输出作为对照，而非根据常见规则编写新期望。简单 AI 注入可控随机数；聪明 AI 覆盖精确终点与归航排除优先级。

再让两种表现适配器消费同一核心动作：验证红绿、绿蓝等非固定组合、关闭席和缺少对面方、两档 AI 与人类；一局四枚全部到达和完整名次流程。对导航、刷新、前进后退、重开和连续换主题执行回调隔离测试。

在两个要求尺寸分别检查首页、设置、3D、2D，包含 resize 与高 DPI；检查加载网络（首页/2D 不请求 Three.js）、控制台、动画与 GPU 资源释放。保留原 3D 视角功能。最后更新 README 和 PROJECT_HANDOVER，不 push、不部署。
